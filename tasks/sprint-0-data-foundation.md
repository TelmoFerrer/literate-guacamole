# Sprint 0 — data foundation

## Goal

Prepare a secure, testable persistence foundation for MyFinance without connecting real financial accounts or importing personal data.

## Scope

- [x] Document the proposed data model and ownership strategy in `docs/DATA_MODEL.md`.
- [ ] Review and approve account, transaction, category, transfer and valuation semantics.
- [ ] Generate and commit the real `pnpm-lock.yaml` from the pinned pnpm version.
- [ ] Add local Supabase configuration and versioned SQL migrations.
- [ ] Implement ownership-safe composite foreign keys and indexes.
- [ ] Enable RLS on every user-owned table.
- [ ] Add database tests proving cross-user reads and writes are denied.
- [ ] Generate TypeScript database types from the migrated schema.
- [ ] Implement Supabase auth/session handling and protected routes.
- [ ] Add manual account entry using synthetic fixtures.

## Acceptance criteria

- A fresh checkout installs dependencies deterministically with frozen lockfile mode.
- The schema has explicit currency and timestamp semantics.
- Every user-owned row is scoped by `user_id`.
- Composite foreign keys prevent cross-user references even if application filters are missing.
- RLS tests cover at least two users, anonymous access, nested relationships and write attempts.
- No production bank credentials, provider tokens or personal financial data are used.
- No live Open Banking or broker integration is required for this sprint.

## Safety gates

- Do not apply migrations to a production Supabase project during development.
- Do not add service-role credentials to browser-visible environment variables.
- Do not import real statements until auth, RLS and deletion/retention behavior have been reviewed.
- Keep source transaction rows immutable and treat fingerprints as matching evidence, not unconditional unique identifiers.

## Dependencies / blockers

- The repository is public. Keep all secrets and real financial data out of Git.
- A reproducible pnpm lockfile must be generated by running the pinned pnpm version in an environment with registry access; never hand-author or fabricate it.
- A Supabase project is not required to review this design. Project credentials are required only when implementing and validating the connected auth flow.
