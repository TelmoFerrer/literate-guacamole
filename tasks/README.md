# Engineering tasks

Tasks are the execution contract between the Product Owner, orchestrator and implementation agents.

## Rules

- Every non-trivial change starts with a task and verifiable acceptance criteria.
- Use [the task template](templates/feature.md).
- Keep one task focused enough to implement and review independently.
- Mark approval requirements explicitly; a task is not authorised merely because an agent can technically perform it.
- Update task status and link the relevant branch/PR when work starts.
- Do not place secrets, account identifiers, real transactions or personal statements in tasks.

## Status vocabulary

- **Proposed:** needs refinement or prioritisation.
- **Ready:** Definition of Ready satisfied and required approvals obtained.
- **In progress:** implementation underway.
- **In review:** PR opened; review or checks pending.
- **Blocked:** waiting for a decision, dependency or external input.
- **Done:** accepted and merged by an authorised human.
